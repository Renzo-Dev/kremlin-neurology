# Архитектура каталогов

## Структура

```
data/
├── public/           # Публичная библиотека (статичная)
│   └── catalog.json  # Каталог публичных документов
└── private/          # Приватная библиотека (изменяемая)
    └── catalog.json  # Каталог приватных документов
```

## Принципы работы

### Публичный каталог (`public/catalog.json`)
- **Статичный** - никогда не изменяется
- Содержит базовые медицинские документы
- Доступен всем пользователям без аутентификации
- 15 документов по неврологии

### Приватный каталог (`private/catalog.json`)
- **Динамический** - файлы добавляются/удаляются
- Содержит пользовательские документы
- Требует аутентификации для доступа
- Изначально пустой `[]`

## API Endpoints

### Получение каталогов
- `GET /api/catalog/public` - публичный каталог
- `GET /api/catalog/private` - приватный каталог (требует аутентификации)
- `GET /api/catalog/paginated` - каталог с пагинацией
- `GET /api/catalog/paginated?type=public` - публичный каталог с пагинацией
- `GET /api/catalog/paginated?type=private` - приватный каталог с пагинацией (требует аутентификации)

### Управление файлами
- `POST /api/catalog` - добавление файла в приватный каталог (требует аутентификации)
- `DELETE /api/catalog` - удаление файла из приватного каталога (требует аутентификации)

### Скачивание файлов
- `POST /api/download` - скачивание публичных файлов
- `POST /api/privateDownload` - скачивание приватных файлов (требует аутентификации)

### Дополнительные функции
- `GET /api/storage/stats` - статистика хранилища
- `POST /api/file/info` - информация о файле

## Безопасность

### Защита на уровне роутинга
- **Middleware цепочка**: все проверки происходят до вызова контроллера
- **PrivateAccessMiddleware**: проверяет GET параметры на `type=private`
- **AuthMiddleware**: защищает все приватные роуты
- **Контроллер**: только бизнес-логика, без проверок безопасности

### Порядок выполнения middleware
1. **PrivateAccessMiddleware** - проверяет приватные параметры в GET запросах
2. **AuthMiddleware** - проверяет аутентификацию для защищенных роутов
3. **ValidationMiddleware** - валидирует входные данные

### Защищенные операции
- Все запросы с `type=private` требуют аутентификации
- Приватные каталоги недоступны без сессии
- Скачивание приватных файлов защищено
- Управление файлами (добавление/удаление) защищено

### Примеры защиты
```
GET /api/catalog/paginated?type=private
↓
PrivateAccessMiddleware → видит type=private → требует аутентификацию
↓
401 Unauthorized (без сессии)

GET /api/catalog/paginated?type=public  
↓
PrivateAccessMiddleware → пропускает (type=public)
↓
200 OK (публичные данные)
```

## Логика работы

1. **Роутинг**: middleware проверяет безопасность до вызова контроллера
2. **Чтение**: `CatalogService::getCatalog($type)` загружает данные из соответствующего файла
3. **Запись**: Все изменения происходят только в `private/catalog.json`
4. **Фильтрация**: Нет необходимости - каждый каталог содержит только свои файлы
5. **Пагинация**: Поддерживается для обоих типов каталогов
6. **Безопасность**: Приватные данные защищены на уровне middleware

## Преимущества новой архитектуры

- ✅ Простота - нет сложной логики фильтрации
- ✅ Производительность - загрузка только нужного каталога
- ✅ Безопасность - четкое разделение публичного и приватного
- ✅ Защита - приватные данные недоступны без аутентификации
- ✅ Разделение ответственности - безопасность в middleware, логика в контроллере
- ✅ Масштабируемость - легко добавлять новые защищенные параметры
- ✅ Поддержка - простая структура файлов
