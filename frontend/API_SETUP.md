# Настройка API для Frontend

## Обзор изменений

Мок данные были заменены на реальное взаимодействие с backend API.

## Основные изменения

### 1. Новый API сервис
- Создан `src/services/apiService.js` вместо `mockApiService.js`
- Реализованы все методы для работы с backend
- Добавлена обработка ошибок и типов ответов

### 2. Обновленные composables
- `useFileAccess.js` - упрощенная аутентификация без автоматической проверки статуса
- `useFileDownload.js` - интегрирован с API для скачивания
- `useFileSearch.js` - готов для работы с реальными данными
- `useApiState.js` - новый composable для мониторинга состояния API

### 3. Обновленные компоненты
- `Library.vue` - интегрирован с новым API сервисом
- Убраны все ссылки на мок данные

## Настройка

### Переменные окружения
Создайте файл `.env.local` в корне frontend:
```bash
VITE_API_URL=http://localhost:5000/api
```

### Решение CORS проблем
Если возникают CORS ошибки:

1. **Проверьте backend CORS настройки** в `backend/src/utils/cors.php`
2. **Убедитесь, что CORS подключается** в `backend/src/index.php`
3. **Проверьте порт frontend** - Vite обычно использует 5173
4. **Тестируйте CORS** через `http://localhost:5000/test-cors.php`

### Backend API endpoints
Убедитесь, что backend предоставляет следующие endpoints:

#### Аутентификация
- `POST /api/auth` - вход в систему

#### Каталоги
- `GET /api/catalog/public` - публичный каталог
- `GET /api/catalog/private` - приватный каталог
- `GET /api/catalog/paginated` - каталог с пагинацией

#### Файлы
- `POST /api/download` - скачивание публичных файлов
- `POST /api/privateDownload` - скачивание приватных файлов
- `POST /api/file/info` - информация о файле
- `GET /api/storage/stats` - статистика хранилища

## Запуск

1. Убедитесь, что backend запущен на порту 5000
2. Запустите frontend:
```bash
cd frontend
npm run dev
```

## Тестирование

### Проверка CORS
1. Откройте в браузере: `http://localhost:5000/test-cors.php`
2. Должен вернуться JSON с сообщением "CORS работает корректно"

### Проверка публичного каталога (без middleware)
1. Откройте в браузере: `http://localhost:5000/test-public.php`
2. Должен вернуться JSON с данными публичного каталога

### Проверка API через middleware
1. Откройте в браузере: `http://localhost:5000/api/catalog/public`
2. Должен вернуться JSON с данными каталога (без ошибки аутентификации)

### Проверка приватного каталога
1. Откройте в браузере: `http://localhost:5000/api/catalog/private`
2. Должна вернуться ошибка 401 "Требуется аутентификация"

## Обработка ошибок

- Автоматическое определение состояния сети
- Проверка доступности API
- Пользовательские сообщения об ошибках
- Retry механизм для загрузки файлов

## Безопасность

- Аутентификация через backend
- Проверка прав доступа к приватным файлам
- Валидация данных на стороне сервера
